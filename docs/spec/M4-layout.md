# M4 레이아웃 스펙 — 집 (거실 + 방 3개)

> **이 문서의 지위**: 좌표와 치수의 **단일 원본(single source of truth)**.
> Claude Code CLI는 이 문서의 표를 `game/src/world/layout.js`에 그대로 옮겨 적고,
> `world/house.js`가 그 데이터에서 벽/바닥/문을 **기계적으로** 생성한다.
> 여기 없는 숫자를 코드에서 새로 만들지 않는다. 필요하면 이 문서를 먼저 고친다.
>
> 작성: Claude 앱(Opus, 1층 = 결정 담당) / 2026-08-15
> 구현: Claude Code CLI (2층) — `main` 브랜치 직접
> 근거: `docs/roadmap.md` §2 M1 스케일표, §4.2 충돌 설계, `handoff-2026-08-15.md` §3

## 0. 왜 이 문서가 먼저인가

`layout.js`는 **소품 배치 · 벽 페이드 · 캐릭터 스폰 · 카메라 튜닝 · 배포 스크린샷**의 공통 입력값이다.
좌표가 흔들리면 그 5개가 전부 재작업된다. roadmap이 M1에 "진짜 산출물은 스케일 수치"라고
게이트를 건 것과 같은 이유로, M4에서 락인되는 것은 코드가 아니라 **이 표**다.

> 카메라 초기 위치가 전부 원점 기준으로 이미 튜닝돼 있다. 집 중심을 옮기면 그게 전부 딸려 온다.

## 2. 방 4칸 (`ROOMS`)

방 사각형은 **벽 중심선 기준**의 바깥 경계다. 실제 걸어다닐 수 있는 내부는 각 변에서 0.06 m 안쪽.

| id | 이름 | x0 | z0 | x1 | z1 | 크기 | 면적 | 바닥색 |
|---|---|---|---|---|---|---|---|---|
| `living` | 거실 | −3 | −3 | 3 | 3 | 6.0 × 6.0 | 36 ㎡ | `0x8a5a3c` (기존) |
| `bedA` | 침실 A (북) | −3 | −7 | 2 | −3 | 5.0 × 4.0 | 20 ㎡ | `0x9a6a45` |
| `study` | 작업실 (동) | 3 | −2 | 7 | 3 | 4.0 × 5.0 | 20 ㎡ | `0x7d5236` |
| `bedB` | 침실 B (남) | −2 | 3 | 2 | 7 | 4.0 × 4.0 | 16 ㎡ | `0x9a6a45` |

**집 전체 footprint**: X ∈ [−3, 7], Z ∈ [−7, 7]. 최대 원점거리 ≈ 9.9 m (모서리 (7,7)).

**동선 검산**: 거실 횡단 6 m ÷ 2.5 m/s = **2.4초**. 침실A 중앙(−0.5,−5) → 침실B 중앙(0,5) 직선 10 m = **4.0초**.
현재 3.6 m 방의 1.4초 대비 "걷는 재미"가 생기는 구간. 10초를 넘기면 지루하므로 이 이상 키우지 않는다.

**바닥 생성 규칙**: 각 방 rect를 사방으로 `WALL_T/2 = 0.06` 확장한 Box로 만든다(벽 아래가 뚫려 보이지 않게).
바닥 메시에 `{ roomId: <id> }` 태그를 붙인다 (`TAG.ROOM_ID` — 이미 정의돼 있으나 아직 미사용. M4에서 처음 쓰인다).
**천장은 만들지 않는다** (내려다보는 카메라).

**폐합 검증 (수동 확인 완료)** — 모든 꼭짓점에서 최소 2개 세그먼트가 만난다:
(−3,−7)·(2,−7)·(−3,−3)⁽ᶜ⁾·(2,−3)·(3,−3)·(3,−2)·(7,−2)·(7,3)·(3,3)⁽ᶜ⁾·(2,3)·(−2,3)·(−3,3)·(−2,7)·(2,7).
⁽ᶜ⁾ 표시는 같은 직선 위 세그먼트가 이어지는 지점(공선 연속) — 빈틈 아님.
**외곽선이 하나의 닫힌 폐곡선**이므로 플레이어가 집 밖으로 나갈 수 없다.

> **현관문은 M4 범위 밖**이다. 바깥으로 나가는 순간 `exterior.js`의 지형 품질이 노출되고
> 콜라이더 없는 무한 평지가 되므로, 배포(M5) 이후 별도 판단.

**색상**: 외벽·공유벽 모두 `0xf1e3cd`(북향) / `0xe7d5ba`(그 외) — 기존 톤 유지.

## 4. 문 3개 (`DOORS`)

문은 **트리거가 아니라 콜라이더 공백**이다 (roadmap §4.2). 문 있는 벽은 세 조각으로 쪼갠다:

- 좌(하) 조각 — `{ solid: true, fadeable: true }`
- 우(상) 조각 — `{ solid: true, fadeable: true }`
- **상인방** y ∈ [2.00, 2.30] — `{ fadeable: true }` **만**. `solid` 를 붙이지 않는다.

이렇게 하면 문 전용 코드가 0줄이 되고, 지오메트리와 충돌이 어긋날 수가 없다.

| 문 | 벽 # | 개구부 중심 | 폭 | 개구부 구간 | 잔여 조각 A | 잔여 조각 B |
|---|---|---|---|---|---|---|
| **D1** living↔bedA | 2 (Z=−3) | X = **−0.5** | 1.30 | X [−1.15, 0.15] | X [−3, −1.15] (1.85) | X [0.15, 2] (1.85) |
| **D2** living↔study | 10 (X=3) | Z = **+0.5** | 1.30 | Z [−0.15, 1.15] | Z [−2, −0.15] (1.85) | Z [1.15, 3] (1.85) |
| **D3** living↔bedB | 14 (Z=3) | X = **0.0** | 1.30 | X [−0.65, 0.65] | X [−2, −0.65] (1.35) | X [0.65, 2] (1.35) |

세 문 모두 벽 구간의 정중앙 — 잔여 조각이 좌우 대칭이라 눈에 거슬리지 않고, 검증도 단순해진다.

**연결성**: bedA·study·bedB가 각각 living에 직접 연결. 방↔방 직통 문 없음.
거실이 허브라 어느 방에서든 다른 방까지 문 2개. 복도를 만들지 않아 벽 세그먼트가 17개로 끝났다.

**문틀 장식(선택)**: 개구부 양옆에 0.06×0.06×2.0 기둥을 `solid` 없이 넣으면 문처럼 보인다. 시간 남으면.

## 5. 기존 코드에 생기는 파급 (⚠️ 놓치면 M4가 깨져 보인다)

### 5.1 `world/exterior.js` — **반드시 같이 고쳐야 함**

집이 원점 반경 2.5 m → **9.9 m**로 커지면서 두 곳이 충돌한다.

**(a) 지면 감쇠 반경.** 현재 `falloff = clamp((dist − 4) / 10)`, 진폭 0.4.
새 집 모서리 dist ≈ 9.9 → 변위 최대 **0.236 m**. 바닥(두께 0.12) 뚫고 올라온다.
→ `(dist − 11) / 10` 으로 변경. `PlaneGeometry(80,80,16,16)` 정점 간격이 5이므로
반경 5·10 고리가 전부 평평해지고 15 고리부터 기복이 생긴다. **정점 간격보다 큰 평탄 반경**을 유지하는 것이 요점
(반경 4일 때 정확히 이 규칙을 어겨서 `4464d4e` 버그가 났다).

**(b) 나무 3그루가 집 안/집 코앞에 박힌다.** `treePositions`에서 **삭제**:
`[-4, -5]`, `[4.5, -4]`, `[5, 4]`.
판정 규칙: 집 bbox X[−3,7]·Z[−7,7]을 1.5 m 확장한 X[−4.5, 8.5]·Z[−8.5, 8.5] 안에 나무 금지.
나머지 9그루(`[-5.5,3] [-8,-8] [7,-9] [-10,5] [9,7] [-12,-3] [11,-2] [-3,-12] [2,-14]`)는 통과.
언덕 6개는 최소 거리 18 m라 전부 안전.

### 5.2 `world/rooms/livingRoom.js` — 벽 제거 + 소품 재배치

**삭제할 것**: 뒷벽 / 왼쪽 벽 / 오른쪽 벽 / 바닥 / 걸레받이 — 전부 `house.js` 소관으로 이관.
이 파일은 **소품 전용**이 된다(램프 클릭 상호작용 포함).

방이 3.6 m → 6.0 m가 되면서 벽 안쪽면이 ±1.74 → **±2.94**로 이동. 벽에 붙어 있던 물건들:

| 소품 | 기존 (x, z) | 신규 (x, z) | 비고 |
|---|---|---|---|
| 책상 그룹 | (0.4, −1.35) | **(0.4, −2.55)** | 깊이 0.55 → 뒷면 −2.825, 벽까지 여유 0.115 |
| 의자 | (0.4, −0.55) | **(0.4, −1.75)** | 책상과의 상대 간격 0.8 유지 |
| 책장 | (−1.6, −0.9) | **(−2.75, −0.9)** | 폭 0.28 → 좌면 −2.89, 여유 0.05 |
| 화분 | (−1.55, 1.15) | **(−2.75, 1.15)** | |
| 벽 액자 | (−0.9, 1.55, −1.725) | **(−0.9, 1.55, −2.88)** | 뒷벽 안쪽면에 밀착 |
| 러그 | (0.2, 0.5) r=0.75 | **(0.2, 0.9) r=1.10** | 방이 커진 만큼 확대 |
| 방석 | (0.65, 0.95) | **(0.9, 1.5)** | |

**벽밀착 일반규칙**: 벽에 붙이는 물건의 중심은 벽 안쪽면에서 `자기 깊이/2 + 0.05` 이상 띄운다.

### 5.3 `main.js` — 조립 순서

```
setupLighting → createHouse(scene)  ← 신규, 벽·바닥·문
              → createLivingRoom()  ← 소품만
              → createBedA/Study/BedB()  ← M4c, Gemini 레인
              → createExterior()
              → createPlayer()
              → rebuildFrom(scene)      ← 반드시 월드 조립 후
              → createFollowCamera()    ← FADEABLE을 생성 시점에 1회 스캔하므로 벽보다 뒤
```
스폰 위치는 `[0, 0, 1.5]` (거실, D3 문 앞 여유 1.5 m).

### 5.4 확인만 필요한 항목 (변경 여부는 CLI가 판단)

- `render/sky.js` 안개 far 값 — 집이 14 m로 길어졌으니 침실A에서 침실B가 안개에 먹히는지 확인
- `config/camera.js` 기본 거리 — 6 m 방에서 캐릭터가 너무 작아 보이는지 확인
- 콜라이더 개수: 벽 조각 ≈ 23 + 소품 ≈ 20 = **43개**. roadmap의 "300개 전엔 브로드페이즈 금지" 기준 안쪽 — **최적화하지 말 것**

## 6. 검증 (리뷰어 대신 스크립트가 판정한다)

이 프로젝트에서 지금까지 잡힌 버그 5건 중 **코드 리뷰로 잡혔을 버그는 0건**이다
(GLSL edge0>edge1, 정점 간격, AudioLoader 콜백 — 전부 실행해야 보임).
따라서 M4의 품질 게이트는 사람 리뷰가 아니라 아래 두 스크립트다. **둘 다 만드는 것이 M4의 산출물에 포함된다.**

### 6.1 `tools/layout-check.mjs` (신규, 순수 node — 브라우저 불필요)

`layout.js`를 import해서 아래를 검사, 실패 시 `process.exit(1)`:

1. 모든 벽이 축정렬 (`x0===x1 || z0===z1`)
2. 모든 문 폭 `≥ 2 × PLAYER.radius + 0.15` (= 0.59)
3. 문 개구부가 벽 구간에 완전히 포함되고, 양쪽 잔여 조각 길이 `≥ 0.10`
4. 방 rect끼리 서로 겹치지 않음
5. **연결성**: 문 그래프에서 모든 방이 `living`으로부터 도달 가능
6. 스폰 지점이 어떤 벽/소품 AABB에도 포함되지 않고, 가장 가까운 콜라이더까지 `≥ 0.3 m`
7. 벽 외곽선 폐합: 모든 세그먼트 끝점이 다른 세그먼트의 끝점과 일치(공선 연속 허용)

### 6.2 `tools/render-check/m4-rooms.mjs` (신규, 헤드리스 크롬)

**문 통과 주행 테스트가 핵심이다.** 스크린샷만 찍으면 "문에 끼는" 버그를 못 잡는다.

- 스폰 → 각 방 중앙까지 **실제 키 입력 시뮬레이션으로 이동**시켜 도달 여부 확인
  (`window.__debug.player.root.position` 폴링, 타임아웃 20초)
- 문 정중앙이 아니라 **개구부 가장자리에서 0.25 m 안쪽**으로도 통과 시도 — 문틀 끼임 검출
- 도달 실패 시 실패 좌표를 출력 (어느 벽에 막혔는지 즉시 특정 가능)
- 방 4개 중앙에서 스크린샷 `m4-living.png`, `m4-bedA.png`, `m4-study.png`, `m4-bedB.png`

**반대 관점**: 방을 4개로 나누지 않고 **거실 하나를 8×8로 크게 만들고 파티션으로 구역만 나누는** 안도 있다.
벽/문/페이드 로직이 전부 사라져서 M4가 하루로 줄고 M5 배포가 앞당겨진다.
그렇게 하지 않는 이유는 원래 목표문에 "방 3개 + 거실"이 명시돼 있고, 벽 페이드·방 점유(`ROOM_ID`)가
이 게임의 유일한 시스템적 재미이기 때문이다. 다만 **일정이 밀리면 이 축소안이 유효한 후퇴 지점**이다.
