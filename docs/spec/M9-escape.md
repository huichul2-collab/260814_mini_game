## 1. 방 배정

시나리오의 "방1/방2/방3"을 실제 방에 배정한다. **기존 드레싱을 가장 적게 버리는 조합**으로 정했다.

| 시나리오 | 방 id | 위치·크기 | 연결 문 | 자물쇠 종류 |
|---|---|---|---|---|
| 메인 | `living` | 중앙 6.0×6.0 | — | 허브 |
| 방1 **서재** | `study` | 동 4.0×5.0 | **D2** | 번호 4자리 |
| 방2 **공방** | `bedA` | 북 5.0×4.0 | **D1** | 방향(상하좌우) |
| 방3 **보관소** | `bedB` | 남 4.0×4.0 | **D3** | 영어 5글자 |
| 탈출 | 마당 | 서 4.0×5.0 | **D4** | 열쇠(조립품) |

**배정 근거**
- `study`에 이미 책상·의자·책장이 있어 서재로 그대로 쓸 수 있다.
- `bedA`가 가장 넓어 벽에 백지+아크릴판을 걸기 좋다.
- `bedB`가 가장 작아 기계 장치 하나만 두면 충분하다.
- 자물쇠 4개가 전부 거실 쪽 벽면에 붙는다 — 허브 구조라 플레이어가 한자리에서 진행 상황을 볼 수 있다.

**폐기되는 것**: `bedA`·`bedB`의 침실 드레싱(침대·옷장 등). `gemini/lane-rooms` 산출물의 상당 부분이 여기서 버려진다.

## 2. 진행 흐름

```
시작(거실, 문 4개 전부 잠김)
  │
  ├─ 거실 시계 조사 → 08:25
  │     └─ D2 번호 자물쇠에 "0825" → 서재 열림
  │
  ├─ 서재: 일기장 조사 → "하늘 · 땅 · 심장 · 바른손"
  │     ├─ 획득: UV 랜턴, 열쇠조각 1/3
  │     └─ D1 방향 자물쇠에 ↑↓←→ → 공방 열림
  │
  ├─ 공방: 백지 + 아크릴판
  │     ├─ UV 랜턴 사용 → 백지에 글자 드러남
  │     ├─ 아크릴판 겹침 → "TRUTH"
  │     ├─ 획득: 철제 톱니바퀴, 열쇠조각 2/3
  │     └─ D3 영어 자물쇠에 "TRUTH" → 보관소 열림
  │
  ├─ 보관소: 기계 장치 홈에 톱니바퀴 끼움
  │     └─ 숨은 서랍 열림 → 열쇠조각 3/3
  │
  └─ 거실 조립 머신에 조각 3개 → 현관 열쇠 완성
        └─ D4 현관문 → 탈출 (엔딩)
```

**순서 강제 방식**: 각 방의 열쇠(단서·아이템)가 이전 방에만 있으므로 순서를 건너뛸 수 없다. 별도의 잠금 로직이 필요 없다.

**막힘(soft-lock) 방지**: 아이템은 한번 얻으면 사라지지 않는다. 톱니바퀴는 사용 후에도 인벤토리에 남긴다(재사용 가능성 차단보다 안전이 우선).

## 3. 퍼즐 4개

### P1 — 번호 자물쇠 (거실 → 서재, D2)

| | |
|---|---|
| 단서 | 거실의 멈춘 시계가 08시 25분을 가리킴 |
| 입력 UI | 4자리 숫자 키패드 (2D 팝업) |
| 정답 | `0825` |
| 보상 | D2 잠금 해제 |
| 실패 시 | "맞지 않는다" 대사, 재시도 무제한 |

### P2 — 방향 자물쇠 (거실 → 공방, D1)

| | |
|---|---|
| 단서 | 서재 책상 위 일기장: "하늘 · 땅 · 심장 · 바른손" |
| 해석 | 하늘=↑, 땅=↓, 심장=←(왼쪽 가슴), 바른손=→(오른손) |
| 입력 UI | 화살표 4버튼, 누른 순서가 기록됨 |
| 정답 | `↑ ↓ ← →` |
| 보상 | D1 잠금 해제 |

> 이 퍼즐만 "말→방향" 번역이 필요해 난이도가 튄다. 막히면 일기장에 힌트 한 줄을 추가하는 걸로 조절한다(`story.js`에서 문자열만 수정).

### P3 — 영어 자물쇠 (거실 → 보관소, D3)

| | |
|---|---|
| 단서 | 공방 벽의 백지 + 구멍 뚫린 아크릴 판 |
| 행동 | ① UV 랜턴 소지 상태로 백지 조사 → 글자가 드러남 ② 아크릴판을 겹침 → 특정 글자만 보임 |
| 입력 UI | 알파벳 5칸 (2D 팝업) |
| 정답 | `TRUTH` |
| 보상 | D3 잠금 해제 |

**구현 주의**: "UV를 비춘다 / 판을 겹친다"를 3D로 만들지 않는다(§6). 백지를 조사하면 2D 팝업이 뜨고, 인벤토리에 UV 랜턴이 있으면 팝업 이미지가 "글자 드러난 버전"으로 바뀐다. 아크릴판도 같은 팝업 안에서 겹치기 토글로 처리한다.

### P4 — 톱니바퀴 조립 (보관소)

| | |
|---|---|
| 단서 | 방 한가운데 기계 장치의 빈 홈 |
| 행동 | 인벤토리의 철제 톱니바퀴를 홈에 끼움 |
| 정답 | 아이템 소지 여부만 판정 (입력 없음) |
| 보상 | 숨은 서랍 열림 → 열쇠조각 3/3 |

### P5 — 열쇠 조립 (거실)

| | |
|---|---|
| 단서 | 거실의 조립 머신 |
| 행동 | 열쇠조각 3개를 모두 소지한 상태로 조사 |
| 보상 | `현관 열쇠` 획득 → D4 해제 가능 |

## 5. 인벤토리 UI

- 화면 **우하단 고정 아이콘**. 클릭하면 격자 패널이 열리고, 다시 누르거나 바깥을 클릭하면 닫힌다.
- 슬롯은 **4×2 = 8칸** 고정. 아이템이 최대 6개라 넉넉하다.
- 각 슬롯: 아이콘(CSS 도형/이모지) + 이름. 클릭하면 하단 대화창에 설명이 뜬다.
- 새 아이템 획득 시 아이콘에 짧은 강조 애니메이션 + 대화창에 "○○을(를) 얻었다".
- **이미지 파일을 쓰지 않는다.** 무빌드·오프라인 원칙 유지.
- 모바일 세로 화면에서 패널 폭 최대 320px, 하단 대화창과 겹치지 않게 배치.

## 6. 구현 원칙 (중요)

### 6.1 퍼즐 상호작용은 전부 2D DOM 팝업으로

3D 월드에서는 **"조사" 클릭까지만** 하고, 자물쇠 입력·아크릴 겹치기·기계 조립은 화면 위 오버레이에서 처리한다.

**이유**: UV로 글자를 드러내는 건 셰이더/텍스처 전환이고, 판을 겹치는 건 3D 조작 UI가 필요하다. 무빌드·순수 ES모듈 파이프라인으로 감당할 규모가 아니다. 방탈출 게임의 표준 방식이기도 하다.

### 6.2 문 잠금은 "개구부를 막는 패널"로

지금 문은 콜라이더 공백이라 **문 전용 코드가 0줄**이다(`M4-layout.md` §4). 이 설계를 깨지 않으려면:

- 개구부 크기의 `doorPanel` 메시를 추가하고 `{ solid: true, interactive: 'lock_D2' }` 태그를 붙인다.
- 해제 시 `panel.visible = false` + `physics/colliders.js`의 `rebuildFrom(scene)` 재호출.
- 콜라이더 전체 재수집이지만 문을 열 때 한 번뿐이라 비용이 없다.

### 6.3 상태는 한 곳에만

`game/src/story/state.js`가 플래그(Set)와 인벤토리(배열)를 단독 보관한다. 다른 모듈은 읽기와 이벤트 구독만 한다. 세이브는 만들지 않는다(1회 플레이 분량).

## 7. 신규 오브젝트 — 조형 방식

**원칙: GLB는 최소한으로.** 기본 도형으로 알아볼 수 있으면 도형으로 만든다. 에셋이 늘수록 스타일 통일이 어려워지고 용량이 커진다.

| 오브젝트 | 방 | 방식 | 근거 |
|---|---|---|---|
| 멈춘 시계 | 거실 | **도형** | 원판 + 바늘 2개(Box). **바늘 각도를 08:25로 코드에서 정확히 지정해야 하므로 GLB가 오히려 불리하다** |
| 열쇠 조립 머신 | 거실 | 도형 | 박스 + 홈 3개(작은 오목 박스) |
| 자물쇠 D1/D2/D3 | 거실 벽 | 도형 | 작은 박스 + 다이얼 원통. 문 옆에 붙는 작은 오브젝트라 디테일 불필요 |
| 일기장 | 서재 | 도형 | 얇은 박스 2장(펼친 책) |
| UV 랜턴 | 서재 | 도형 | 원통 + 원뿔 헤드 |
| 백지 | 공방 벽 | 도형 | 평면(Plane) |
| 아크릴 판 | 공방 벽 | 도형 | 반투명 평면 + 구멍은 텍스처 없이 작은 박스 배열로 |
| 작업대 | 공방 | 도형 | 박스 + 다리 |
| 기계 장치 | 보관소 | 도형 | 원통 + 박스 조합, 홈은 오목 박스 |
| 숨은 서랍 | 보관소 | 도형 | 박스, 열리면 위치만 이동 |
| 열쇠 조각 ×3 | 각 방 | 도형 | 작은 박스. 인벤토리에서는 CSS 아이콘 |
| **철제 톱니바퀴** | 공방 | **GLB 후보** | 이빨 있는 원판은 기본 도형 조합으로 자연스럽게 만들기 어려운 유일한 항목 |
| **현관 열쇠** | 조립품 | **GLB 후보** | 손에 드는 상징적 오브젝트. 도형으로도 가능하나 엔딩 연출에 쓰이면 품질 차이가 보인다 |

**결론: GLB는 톱니바퀴 1개, 많아야 열쇠까지 2개.** 나머지 11개는 전부 기본 도형.

에셋을 받는다면 CC0 우선(Poly Pizza / Quaternius). 받은 뒤 `tools/asset-check.mjs`로 애니메이션·스킨·용량을 반드시 검증하고 `ATTRIBUTION.md`에 실제 출처를 기재한다 — 지어낸 에셋과 허위 출처 사고가 이미 한 번 있었다.

## 9. 검증

- `tools/render-check/interaction-check.mjs` — 씬의 interactive id ↔ `story.js` 키 대조(기존)
- **신규 `tools/render-check/escape-flow.mjs`** — 시나리오 전체를 스크립트로 클리어한다.
  시작 → 시계 조사 → 자물쇠 입력 → 방 진입 → … → 탈출까지 자동 주행하고,
  각 단계에서 기대한 플래그·인벤토리 상태가 맞는지 검사한다.
  **이게 방탈출 게임의 최종 회귀 테스트다** — 하나라도 막히면 게임이 클리어 불가능하다는 뜻이므로 즉시 FAIL.
- 모든 렌더 검사에 **절대 하한**(평균휘도 ≥ 15, 검정비율 < 50%, 최대픽셀 ≥ 200)을 비율 검사보다 **먼저** 둔다.

## 10. M9-B 상세 — 문 잠금 + 퍼즐 P1

> 추가: 2026-08-18 (1층)
> **완료 조건 하나**: 시작 시 서재에 못 들어가고, 거실 시계를 조사한 뒤 D2 자물쇠에 `0825`를 넣으면 들어갈 수 있다.

### 10.1 이 단계에서 잠그는 문은 **D2 하나뿐**

게임 완성본에서는 문 4개가 전부 잠겨야 하지만, M9-B의 목적은 **한 사이클(단서 → 퍼즐 → 해제 → 진행)이 끝까지 도는 걸 확인하는 것**이다. 나머지 문이 열려 있어야 테스트 주행이 자유롭고, 실패했을 때 원인 범위가 좁다.

`story.js`의 `LOCKS`에 D2만 넣는다. D1·D3·D4는 M9-C에서 **데이터 한 줄씩** 추가하면 된다 — 코드는 안 고친다.

### 10.2 잠금 패널 (`world/doorLock.js`)

문 개구부를 막는 판을 하나 넣고, 해제 시 숨긴다. `M4-layout.md` §4의 "문 = 콜라이더 공백" 설계를 깨지 않는 유일한 방법이다.

| 항목 | 값 |
|---|---|
| 크기 | 개구부 폭 × `DOOR_H`(2.0) × `WALL_T`(0.12) |
| 위치 | 해당 문 개구부의 정중앙, 벽 중심선에 정렬 |
| 태그 | `{ solid: true, fadeable: true, interactive: 'lock_D2' }` |
| 색 | `0x5a3826` (어두운 나무색 — 벽과 구분되어야 잠긴 문임이 보인다) |
| 장식 | 패널 중앙 높이 1.1 m에 작은 원통 다이얼(반지름 0.07, 두께 0.03, `0x2e2a3a`). `solid` 없음 |

**자물쇠를 별도 오브젝트로 만들지 않는다.** 패널 자체가 클릭 대상이다. 오브젝트를 하나 더 만들면 좌표·크기·클릭 판정이 늘고, "문을 클릭한다"가 플레이어에게 더 직관적이다. 다이얼은 순수 장식이다.

**해제 절차** — 이 순서를 지켜야 콜라이더가 어긋나지 않는다:
```
panel.visible = false
panel.userData.solid = false      ← 반드시 태그도 지운다
rebuildFrom(scene)                 ← 콜라이더 재수집
```
`rebuildFrom`은 씬 전체 traverse(177개)지만 문을 열 때 한 번뿐이라 비용이 없다.

### 10.3 거실 시계 (`props/clock.js`) — GLB 아님

원판 + 바늘 2개. **바늘 각도를 코드에서 정확히 지정해야 하므로 도형이 필수다**(§7 참고).

| 부품 | 형상 | 값 |
|---|---|---|
| 판 | `CylinderGeometry(0.22, 0.22, 0.05, 24)` | `rotation.x = π/2`로 세워 벽에 평행하게 |
| 테두리 | `CylinderGeometry(0.24, 0.24, 0.04, 24)` | 판 뒤, 어두운 색 |
| 시침 | `BoxGeometry(0.02, 0.13, 0.01)` | 회전 중심이 아래 끝이 되도록 오프셋 |
| 분침 | `BoxGeometry(0.015, 0.19, 0.01)` | 같음 |

**바늘 각도 (12시 방향 = +Y 기준, 시계방향)**

```
시침 = (8 % 12) × 30° + 25 × 0.5° = 240 + 12.5 = 252.5°
분침 = 25 × 6°                     = 150.0°
```

three.js에서 시계방향 회전은 `rotation.z = -각도(라디안)`이다. **부호를 반대로 넣으면 8시 25분이 3시 35분처럼 보이므로**, 검증 스크립트에서 각도를 직접 읽어 확인한다(§10.6).

시각 자체(`08:25`)는 `game/story.js`에 두고 코드가 각도를 계산한다. 정답을 바꾸면 바늘도 같이 움직여야 하기 때문이다 — **단서와 정답이 두 곳에 따로 적히면 반드시 어긋난다.**

### 10.4 임시 좌표 (배치맵 오면 교체)

배치맵이 아직 없으므로 임시값이다. `furniture.js` 항목이라 나중에 **한 줄 수정**으로 옮긴다.

| 오브젝트 | 위치 | 근거 |
|---|---|---|
| 거실 시계 | `pos: [-2.90, 1.60, -2.00]`, `rotY: Math.PI/2` | 거실 서벽 안쪽면(X=−2.94)에 밀착. 현관 D4 개구부(Z −0.65~0.65)를 피해 Z=−2.0 |

### 10.6 검증 — `tools/render-check/escape-flow.mjs` (신규)

**규칙 9에 따라 이 스크립트는 스크린샷을 찍지 않는다.** 진행 가능 여부만 판정한다.

1. `CLOCK_TIME`으로 계산한 4자리 문자열이 `PUZZLES.P1.answer`와 일치하는가 (순수 node, 브라우저 불필요)
2. 시계 바늘의 실제 `rotation.z`가 −252.5°/−150.0°와 일치하는가 (부호 실수 검출)
3. 시작 시 D2를 통과할 수 없다 — 서재 방향으로 3초 이동해도 `study` 영역에 못 들어간다
4. 시계를 조사하면 대사가 뜨고 그 안에 시각 정보가 들어 있다
5. D2 패널을 클릭하면 키패드 모달이 뜬다
6. 오답(`1234`) 입력 → 모달이 실패를 알리고 문은 그대로 잠겨 있다
7. 정답(`0825`) 입력 → 모달이 닫히고, **실제로 걸어서 서재에 진입한다**
8. 해제 후 콜라이더 개수가 패널 하나만큼 줄었다

7번이 핵심이다. "플래그가 켜졌다"가 아니라 **"실제로 지나갈 수 있다"**를 봐야 한다.

### 10.7 이 단계에서 깨지는 기존 검증

패널 메시가 하나 늘어나므로 **`scene-diff`가 반드시 실패한다.** 이건 의도된 변경이므로:

- `scene-dump` 기준을 갱신하고, 커밋 메시지에 "패널 1개 추가로 메시 177 → 178" 처럼 **증감 이유를 명시**한다
- `visual-diff` baseline도 갱신한다 (거실 시계 + D2 패널이 화면에 나타난다)
- **기준 갱신은 반드시 별도 커밋으로** 남긴다. 코드 변경과 섞이면 나중에 "이때 왜 기준이 바뀌었지"를 추적할 수 없다

## 12.2 새 메커니즘 — 조건부 설명(`variants`)

같은 오브젝트가 **소지 아이템·플래그·조사 횟수**에 따라 다른 설명을 낸다.
이게 §12의 핵심이고, 없으면 아래 대부분이 구현 불가다.

```js
// story.js OBJECTS 확장
'living.machine': {
  name: '알 수 없는 기계',
  variants: [
    { requires: { items: ['key_piece_1'] },
      text: '구멍 세 개. 열쇠 조각이 들어갈 것 같다.' },
    { text: '구멍이 세 개 뚫려 있다. 용도를 알 수 없다.' },   // 조건 없음 = 기본, 항상 마지막
  ],
},
```

- **위에서부터 첫 번째로 조건을 만족하는 variant**를 쓴다. 조건 없는 항목이 기본값이며 배열 끝에 둔다.
- 조건 키: `items`(전부 보유해야 함) · `flags`(전부 세워져야 함) · `visitedAtLeast`(이 오브젝트 조사 횟수)
- 기존 `text` 단일 필드도 계속 지원한다(하위호환). `variants`가 있으면 그쪽이 우선.
- **`variants`가 있는데 조건 없는 기본 항목이 하나도 없으면 검증에서 FAIL** — 설명이 안 뜨는 오브젝트가 생긴다.

## 12.5 공방 — 도구 획득 + UV 2단계

| 오브젝트 | 조치 |
|---|---|
| **상자**(기존) | `visitedAtLeast` 2단계 함정. 1회차 "밑에 뭔가 쓰여 있을까? 들어볼까." → 2회차 "힘들게 들었다. 아무것도 없다." |
| **작업대**(기존) | "각종 작업 흔적이 남아 있다. 붉은 자국은… 핏자국 같다." |
| **공구상자**(기존) | "낡은 공구들이 가득하다." → **파이프렌치 획득**, flag `got_wrench` |
| **백지** | **2단계로 분리**(아래) |

**P3 백지 — 힌트를 두 단계로 쪼갠다**

```
1단계 (UV 미보유)  : "빈 종이다. 아무것도 쓰여 있지 않다."
2단계 (UV 보유)    : "자외선을 비추자 글자가 떠오른다." → 팝업에 글자 격자 표시
3단계 (팝업 안에서 아크릴판 겹치기 토글) : 특정 글자만 남아 TRUTH
```

기존에는 한 번에 답이 나왔다. **"랜턴을 비춘다"와 "판을 겹친다"가 별개의 발견**이 되도록 나눈다.
아크릴 겹치기 토글은 백지 팝업 **안에** 둔다 — 아크릴판을 따로 조사하면 "구멍이 뚫린 판이다" 정도만.

## 12.6 보관소 — 다이얼 퍼즐 (P4 대체)

기존 "톱니 끼우면 열림"을 **톱니 + 다이얼 2단**으로 바꾼다(사용자 결정).

```
톱니 미보유 : "축이 비어 있다. 무언가 끼워야 돌아갈 것 같다."
톱니 보유   : 톱니 장착 → 다이얼 활성화 → 회전 입력 UI
정답        : 좌 3회 · 우 4회 · 좌 1회
```

`story.js`: `answer: 'L3R4L1'`
`modal.js` 신규 타입 **`dial`**:
- 좌회전 / 우회전 버튼 2개 + 현재까지 입력 표시(`◀3 ▶4 ◀…`)
- 같은 방향 연속 클릭은 카운트 누적, **방향이 바뀌면 한 구간 확정**
- 되돌리기 버튼 + 확인 버튼. 모바일에서 버튼 44px 이상
- 오답 시 입력 초기화 + "헛돈다."

## 12.9 검증

- `escape-flow.mjs`를 **새 경로로 갱신** — 되돌아가기 구간(공방→서재 캐비닛→보관소)이 반드시 포함돼야 한다.
  마지막 항목은 여전히 "시작→탈출 자동 클리어".
- **신규: 함정 오답 테스트.** 1224·0035를 D2에 넣으면 열리지 않고, 0825만 열린다.
  다이얼도 ①③에서 유도되는 오답(`L3`, `L13`)이 안 열리는지 확인.
- **신규: `variants` 정합성 검사**(순수 node) — `variants`를 가진 모든 오브젝트에
  조건 없는 기본 항목이 정확히 하나 있는가. 없으면 FAIL.
- `interaction-check`에 §서재 누락 사고 재발 방지용 **부재 검사**가 이미 들어갔어야 한다.
  신규 오브젝트도 전부 id를 갖는지 확인.
- 책장 조형의 실제 책 개수 = `story.js` 데이터 권수인지 대조.
