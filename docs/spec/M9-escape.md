## 1. 방 배정

시나리오의 "방1/방2/방3"을 실제 방에 배정한다. **기존 드레싱을 가장 적게 버리는 조합**으로 정했다.

| 시나리오 | 방 id | 위치·크기 | 연결 문 | 자물쇠 종류 |
|---|---|---|---|---|
| 메인 | `living` | 중앙 6.0×6.0 | — | 허브 |
| 방1 **서재** | `study` | 동 4.0×5.0 | **D2** | 번호 4자리 |
| 방2 **공방** | `bedA` | 북 5.0×4.0 | **D1** | 방향(상하좌우) |
| 방3 **보관소** | `bedB` | 남 4.0×4.0 | **D3** | 영어 5글자 |
| 탈출 | 마당 | 서 4.0×5.0 | **D4** | 열쇠(조립품) |

**배정 근거**
- `study`에 이미 책상·의자·책장이 있어 서재로 그대로 쓸 수 있다.
- `bedA`가 가장 넓어 벽에 백지+아크릴판을 걸기 좋다.
- `bedB`가 가장 작아 기계 장치 하나만 두면 충분하다.
- 자물쇠 4개가 전부 거실 쪽 벽면에 붙는다 — 허브 구조라 플레이어가 한자리에서 진행 상황을 볼 수 있다.

**폐기되는 것**: `bedA`·`bedB`의 침실 드레싱(침대·옷장 등). `gemini/lane-rooms` 산출물의 상당 부분이 여기서 버려진다.

## 2. 진행 흐름

```
시작(거실, 문 4개 전부 잠김)
  │
  ├─ 거실 시계 조사 → 08:25
  │     └─ D2 번호 자물쇠에 "0825" → 서재 열림
  │
  ├─ 서재: 일기장 조사 → "하늘 · 땅 · 심장 · 바른손"
  │     ├─ 획득: UV 랜턴, 열쇠조각 1/3
  │     └─ D1 방향 자물쇠에 ↑↓←→ → 공방 열림
  │
  ├─ 공방: 백지 + 아크릴판
  │     ├─ UV 랜턴 사용 → 백지에 글자 드러남
  │     ├─ 아크릴판 겹침 → "TRUTH"
  │     ├─ 획득: 철제 톱니바퀴, 열쇠조각 2/3
  │     └─ D3 영어 자물쇠에 "TRUTH" → 보관소 열림
  │
  ├─ 보관소: 기계 장치 홈에 톱니바퀴 끼움
  │     └─ 숨은 서랍 열림 → 열쇠조각 3/3
  │
  └─ 거실 조립 머신에 조각 3개 → 현관 열쇠 완성
        └─ D4 현관문 → 탈출 (엔딩)
```

**순서 강제 방식**: 각 방의 열쇠(단서·아이템)가 이전 방에만 있으므로 순서를 건너뛸 수 없다. 별도의 잠금 로직이 필요 없다.

**막힘(soft-lock) 방지**: 아이템은 한번 얻으면 사라지지 않는다. 톱니바퀴는 사용 후에도 인벤토리에 남긴다(재사용 가능성 차단보다 안전이 우선).

## 3. 퍼즐 4개

### P1 — 번호 자물쇠 (거실 → 서재, D2)

| | |
|---|---|
| 단서 | 거실의 멈춘 시계가 08시 25분을 가리킴 |
| 입력 UI | 4자리 숫자 키패드 (2D 팝업) |
| 정답 | `0825` |
| 보상 | D2 잠금 해제 |
| 실패 시 | "맞지 않는다" 대사, 재시도 무제한 |

### P2 — 방향 자물쇠 (거실 → 공방, D1)

| | |
|---|---|
| 단서 | 서재 책상 위 일기장: "하늘 · 땅 · 심장 · 바른손" |
| 해석 | 하늘=↑, 땅=↓, 심장=←(왼쪽 가슴), 바른손=→(오른손) |
| 입력 UI | 화살표 4버튼, 누른 순서가 기록됨 |
| 정답 | `↑ ↓ ← →` |
| 보상 | D1 잠금 해제 |

> 이 퍼즐만 "말→방향" 번역이 필요해 난이도가 튄다. 막히면 일기장에 힌트 한 줄을 추가하는 걸로 조절한다(`story.js`에서 문자열만 수정).

### P3 — 영어 자물쇠 (거실 → 보관소, D3)

| | |
|---|---|
| 단서 | 공방 벽의 백지 + 구멍 뚫린 아크릴 판 |
| 행동 | ① UV 랜턴 소지 상태로 백지 조사 → 글자가 드러남 ② 아크릴판을 겹침 → 특정 글자만 보임 |
| 입력 UI | 알파벳 5칸 (2D 팝업) |
| 정답 | `TRUTH` |
| 보상 | D3 잠금 해제 |

**구현 주의**: "UV를 비춘다 / 판을 겹친다"를 3D로 만들지 않는다(§6). 백지를 조사하면 2D 팝업이 뜨고, 인벤토리에 UV 랜턴이 있으면 팝업 이미지가 "글자 드러난 버전"으로 바뀐다. 아크릴판도 같은 팝업 안에서 겹치기 토글로 처리한다.

### P4 — 톱니바퀴 조립 (보관소)

| | |
|---|---|
| 단서 | 방 한가운데 기계 장치의 빈 홈 |
| 행동 | 인벤토리의 철제 톱니바퀴를 홈에 끼움 |
| 정답 | 아이템 소지 여부만 판정 (입력 없음) |
| 보상 | 숨은 서랍 열림 → 열쇠조각 3/3 |

### P5 — 열쇠 조립 (거실)

| | |
|---|---|
| 단서 | 거실의 조립 머신 |
| 행동 | 열쇠조각 3개를 모두 소지한 상태로 조사 |
| 보상 | `현관 열쇠` 획득 → D4 해제 가능 |

## 5. 인벤토리 UI

- 화면 **우하단 고정 아이콘**. 클릭하면 격자 패널이 열리고, 다시 누르거나 바깥을 클릭하면 닫힌다.
- 슬롯은 **4×2 = 8칸** 고정. 아이템이 최대 6개라 넉넉하다.
- 각 슬롯: 아이콘(CSS 도형/이모지) + 이름. 클릭하면 하단 대화창에 설명이 뜬다.
- 새 아이템 획득 시 아이콘에 짧은 강조 애니메이션 + 대화창에 "○○을(를) 얻었다".
- **이미지 파일을 쓰지 않는다.** 무빌드·오프라인 원칙 유지.
- 모바일 세로 화면에서 패널 폭 최대 320px, 하단 대화창과 겹치지 않게 배치.

## 6. 구현 원칙 (중요)

### 6.1 퍼즐 상호작용은 전부 2D DOM 팝업으로

3D 월드에서는 **"조사" 클릭까지만** 하고, 자물쇠 입력·아크릴 겹치기·기계 조립은 화면 위 오버레이에서 처리한다.

**이유**: UV로 글자를 드러내는 건 셰이더/텍스처 전환이고, 판을 겹치는 건 3D 조작 UI가 필요하다. 무빌드·순수 ES모듈 파이프라인으로 감당할 규모가 아니다. 방탈출 게임의 표준 방식이기도 하다.

### 6.2 문 잠금은 "개구부를 막는 패널"로

지금 문은 콜라이더 공백이라 **문 전용 코드가 0줄**이다(`M4-layout.md` §4). 이 설계를 깨지 않으려면:

- 개구부 크기의 `doorPanel` 메시를 추가하고 `{ solid: true, interactive: 'lock_D2' }` 태그를 붙인다.
- 해제 시 `panel.visible = false` + `physics/colliders.js`의 `rebuildFrom(scene)` 재호출.
- 콜라이더 전체 재수집이지만 문을 열 때 한 번뿐이라 비용이 없다.

### 6.3 상태는 한 곳에만

`game/src/story/state.js`가 플래그(Set)와 인벤토리(배열)를 단독 보관한다. 다른 모듈은 읽기와 이벤트 구독만 한다. 세이브는 만들지 않는다(1회 플레이 분량).

## 7. 신규 오브젝트 — 조형 방식

**원칙: GLB는 최소한으로.** 기본 도형으로 알아볼 수 있으면 도형으로 만든다. 에셋이 늘수록 스타일 통일이 어려워지고 용량이 커진다.

| 오브젝트 | 방 | 방식 | 근거 |
|---|---|---|---|
| 멈춘 시계 | 거실 | **도형** | 원판 + 바늘 2개(Box). **바늘 각도를 08:25로 코드에서 정확히 지정해야 하므로 GLB가 오히려 불리하다** |
| 열쇠 조립 머신 | 거실 | 도형 | 박스 + 홈 3개(작은 오목 박스) |
| 자물쇠 D1/D2/D3 | 거실 벽 | 도형 | 작은 박스 + 다이얼 원통. 문 옆에 붙는 작은 오브젝트라 디테일 불필요 |
| 일기장 | 서재 | 도형 | 얇은 박스 2장(펼친 책) |
| UV 랜턴 | 서재 | 도형 | 원통 + 원뿔 헤드 |
| 백지 | 공방 벽 | 도형 | 평면(Plane) |
| 아크릴 판 | 공방 벽 | 도형 | 반투명 평면 + 구멍은 텍스처 없이 작은 박스 배열로 |
| 작업대 | 공방 | 도형 | 박스 + 다리 |
| 기계 장치 | 보관소 | 도형 | 원통 + 박스 조합, 홈은 오목 박스 |
| 숨은 서랍 | 보관소 | 도형 | 박스, 열리면 위치만 이동 |
| 열쇠 조각 ×3 | 각 방 | 도형 | 작은 박스. 인벤토리에서는 CSS 아이콘 |
| **철제 톱니바퀴** | 공방 | **GLB 후보** | 이빨 있는 원판은 기본 도형 조합으로 자연스럽게 만들기 어려운 유일한 항목 |
| **현관 열쇠** | 조립품 | **GLB 후보** | 손에 드는 상징적 오브젝트. 도형으로도 가능하나 엔딩 연출에 쓰이면 품질 차이가 보인다 |

**결론: GLB는 톱니바퀴 1개, 많아야 열쇠까지 2개.** 나머지 11개는 전부 기본 도형.

에셋을 받는다면 CC0 우선(Poly Pizza / Quaternius). 받은 뒤 `tools/asset-check.mjs`로 애니메이션·스킨·용량을 반드시 검증하고 `ATTRIBUTION.md`에 실제 출처를 기재한다 — 지어낸 에셋과 허위 출처 사고가 이미 한 번 있었다.

## 9. 검증

- `tools/render-check/interaction-check.mjs` — 씬의 interactive id ↔ `story.js` 키 대조(기존)
- **신규 `tools/render-check/escape-flow.mjs`** — 시나리오 전체를 스크립트로 클리어한다.
  시작 → 시계 조사 → 자물쇠 입력 → 방 진입 → … → 탈출까지 자동 주행하고,
  각 단계에서 기대한 플래그·인벤토리 상태가 맞는지 검사한다.
  **이게 방탈출 게임의 최종 회귀 테스트다** — 하나라도 막히면 게임이 클리어 불가능하다는 뜻이므로 즉시 FAIL.
- 모든 렌더 검사에 **절대 하한**(평균휘도 ≥ 15, 검정비율 < 50%, 최대픽셀 ≥ 200)을 비율 검사보다 **먼저** 둔다.
