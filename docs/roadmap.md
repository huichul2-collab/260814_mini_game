# 로드맵 — 방 1개에서 집 한 채까지

## Context

`game/`은 현재 **단일 `main.js` 340줄**에 방 1개(바닥+벽3), 가구 몇 개, 스탠드 클릭 1종이 들어있다. 여기서 최종 목표까지 가야 한다:

> 방 3개 + 거실을 포함한 집 · 사람 캐릭터 · 무료 에셋 가져와 수정 · 마우스/키보드 인터랙션 · BGM/효과음 · 호스팅 배포

확정된 4개 축:

| 축 | 결정 | 파급 |
|---|---|---|
| 카메라/조작 | **3인칭 추적** (WASD + 마우스) | 충돌처리·벽 페이드·걷기 애니메이션이 전부 필수가 됨 |
| 캐릭터 | Poly Pizza 등 외부 에셋, **텍스처 적용 연습이 목적** | 스타일 불일치를 감수하는 학습 트랙 |
| 아트 방향 | **sample1 쪽** (면셰이딩+색보정+그레인+안개, 외곽선 제거) | 공용 재질 API가 파괴적으로 바뀜 |
| 배포 | **집 구조 완성 시점에 공개** | 그 전까지는 비공개 기술검증만 |

이 문서는 순서·병렬화·체크리스트를 정한다.

## 1. 이런 걸 보통 어떻게 계획하는가

나열된 목록은 **기능 목록(가로 방향)**이다. 잘 굴러가는 계획은 이걸 **세로로 다시 자른다.**

**① 수직 슬라이스 우선.** 방 4개를 만들고 캐릭터를 넣는 게 아니라, **방 1개 안에서 모든 요소가 얇게 다 돌아가게** 만든 뒤 개수를 늘린다. 통합 문제(캐릭터가 벽을 뚫는다, 에셋 스케일이 안 맞는다)는 방 1개에서 발견하면 1/4 비용이다.

**② 제약 축을 먼저 결정** — ✅ 완료. 카메라 방식을 1번으로 정한 이유. 나중에 바꾸면 그 전 콘텐츠가 통째로 날아간다.

**③ 파이프라인이 콘텐츠보다 먼저.** 지금은 소품이 전부 `makeMesh(new THREE.BoxGeometry(...))` 손코딩이다. 5개까진 괜찮지만 집 한 채분(50~60개)을 이렇게 만든 뒤 GLTF로 갈아타면 **전부 버리는 작업**이 된다.

**④ 모듈 분리는 병렬화의 전제.** 파일이 하나면 병렬 작업 가능량은 **정확히 0**이다. 나중 정리 작업이 아니라 선행 작업이다.

**⑤ 파괴적 변경은 일찍.** 외곽선 제거 + 면셰이딩 전환은 모든 모듈이 쓰는 `makeMesh`를 바꾼다. **공용 API를 깨는 변경은 그 위에 콘텐츠가 쌓이기 전에.**

**⑥ 스코프 폭탄은 명시적으로 격리.** `3d-game-handoff.md`가 이미 최대 리스크로 지목한 항목들.

## 3. 병렬화

**M0 이전 병렬 가능 작업은 0개다.** M0 이후 파일 소유권을 레인별로 분리한다:

```
M0 (직렬) ──┬── A 이동/충돌   physics/*, player/*
            ├── B 카메라      camera/*
            ├── C 룩          render/post/*, sky, lighting, world/exterior
            │                 + materials.js 배타적 소유
            ├── D 월드        world/layout, house, rooms/*     ← 임계경로
            └── E 에셋/오디오  assets/*, audio/*, ui/*
```

**충돌 해소 규칙 4가지:**
- **`main.js`·`index.html`은 통합자 전용.** 각 레인은 `init()` 하나만 노출하고 스스로 루프에 등록 → 부트스트랩은 레인당 한 줄만 늘어남
- **`materials.js`는 M0 이후 C만 수정.** D는 동결된 `makeMesh`를 소비만 함
- **config를 레인별 파일로 쪼갠다** (`config/look.js`, `world.js`, `player.js`, `camera.js`, `audio.js`). 단일 `config.js`는 가장 흔한 충돌 지점이고, 파일 4개 더 만드는 게 제일 싼 해결책
- **소품 추가는 코드가 아니라 데이터로.** `manifest.js`에 `{id, url, pos, rotY, fitSize, fallbackColor}` 한 줄 추가 → append-only라 충돌이 구조적으로 불가능

**진짜 직렬인 것**: A는 하드코딩 스텁 레이아웃으로 개발 가능하지만 최종 문폭 튜닝은 D 이후. 걷기 애니메이션은 리깅 에셋(E) 이후.

> **실전에서 드러난 추가 교훈** (M0~M3 진행 후): 위 레인 분리는 **파일 경계**만 다뤘지 **물리적 작업 디렉터리 분리**는 안 다뤘다. Gemini/Antigravity가 이 저장소를 별도로 클론하지 않고 Claude Code 세션과 같은 폴더에서 브랜치를 전환하면, 브랜치를 바꾸는 쪽이 다른 쪽의 커밋 안 된 작업까지 같이 끌고 가버리는 사고가 실제로 났다(자세한 경위는 `dev-log.md` 2026-08-15 (7)(8) 항목). **파일 소유권 분리 + 물리적 폴더 분리가 둘 다 있어야** 병렬 작업이 안전하다. `docs/handoff/gemini-lane-*.md` 지시서는 이제 전부 "-1. 작업 공간 분리" 섹션으로 별도 클론을 강제한다.

## 4. 기술 설계

### 4.1 vendoring (11개 파일, 확인 완료)
```
vendor/jsm/                        ← upstream examples/jsm 구조를 그대로 미러
  loaders/GLTFLoader.js
  utils/BufferGeometryUtils.js  utils/SkeletonUtils.js
  postprocessing/{EffectComposer,Pass,ShaderPass,MaskPass,RenderPass,OutputPass}.js
  shaders/{CopyShader,OutputShader}.js
  controls/OrbitControls.js        ← vendor/ 에서 이동
```
```json
{ "three": "./vendor/three.module.js", "three/addons/": "./vendor/jsm/" }
```
> **구조 미러가 필수인 이유**: importmap 값은 문서 기준으로 해석되지만, 모듈 *내부*의 상대 specifier(`'../utils/BufferGeometryUtils.js'`)는 **그 모듈 자신의 URL 기준**으로 해석되며 importmap을 아예 거치지 않는다. 평평하게 넣으면 GLTFLoader가 404난다.
> `three.module.js`/`three.core.min.js`는 서로 상대 import하므로 **옮기지 않는다.** 기존 정확경로 OrbitControls 키는 삭제(three가 두 번 로드되는 사고 방지).

### 4.2 이동 & 충돌 (물리엔진 없이)
캐릭터 = XZ 평면의 **원**(반지름 0.22), Y는 v1에서 무시. 콜라이더는 빌드 시 `Box3`에서 뽑아낸 **2D AABB 배열**.

**축분리(X 먼저, Z 나중) 대신 MTV 최소이동 밀어내기를 쓴다.** 축분리는 모서리와 문틀(두 기둥이 동시에 겹침)에서 멈춰버리고, 탭 전환 후 dt 급증으로 지오메트리 안에 들어가면 복구가 안 된다. MTV는 미끄러짐이 공짜로 나오고 안에 갇혀도 빠져나온다. 3회 반복이면 문틀+모서리에 충분하다.
> **원의 중심이 박스 내부에 들어간 경우를 반드시 처리해야 한다** — 가장 짧은 면으로 밀어내지 않으면 관통한다. 다들 빠뜨리는 분기다.
> **브로드페이즈는 만들지 않는다.** 40~80개 × 3회 × 60Hz는 무시할 연산량. 300개 넘기 전엔 조기 최적화다.

**문 = 콜라이더 공백** (트리거 볼륨 아님). 문 있는 벽을 좌·우·상인방 3개 박스로 쪼개고 **상인방에만 `solid` 태그를 안 붙인다.** 문 전용 코드가 0줄이 된다. 같은 데이터가 지오메트리와 충돌을 동시에 만들므로 둘이 어긋날 수가 없다.

**결합 제거**: 월드 모듈은 `physics/`를 import하지 않고 `userData.solid`만 태깅. 월드 구축 후 `rebuildFrom(root)`가 한 번 traverse하며 수집. 화살표는 `world → tags.js` 뿐.
> **모든 solid 벽은 축정렬 유지.** 45° 회전한 벽에 `Box3.setFromObject`를 쓰면 거대한 AABB가 나와 보이지 않는 벽이 생긴다.

**프레임 순서**: `입력 → 의도 → 충돌해결 → 위치확정 → 믹서 → 카메라 → 벽페이드 → 렌더`
- `dt = min(getDelta(), 1/30)` **클램프 필수** — 탭 복귀 시 3초짜리 dt가 집 전체를 관통시킨다
- 이동 방향은 `camera.quaternion`이 아니라 **`followCamera.yaw`에서** 유도 (한 프레임 지연 + 역방향 결합 방지)

### 4.3 추적 카메라 + 벽 페이드
- **감쇠는 반드시 `1 - exp(-λ·dt)`.** 고정 alpha(0.1)는 144Hz에서 6배 빠르고 30fps에서 깨진다. 개발 머신에선 안 보이는 가장 흔한 버그
- **위치와 lookAt에 같은 스무딩 값**을 쓴다. 따로 감쇠하면 헤엄치는 이중 지연이 생김
- **레이캐스트는 프레임당 1개**(`캐릭터 → 카메라 목표`). 카메라 당김과 벽 페이드가 **같은 ray를 공유** — 따로 쏘면 두 판정이 어긋난다
- **당김은 즉시, 복귀는 천천히**(비대칭). 대칭이면 모서리에서 물러설 때마다 150ms씩 벽을 통과해 보인다
- v1은 **포인터락 대신 드래그 회전.** itch.io는 iframe이라 포인터락+Esc+전체화면 조합이 실제 마찰이 크다
- 페이드 목표는 0이 아니라 **0.18** (0이면 지붕 없는 집처럼 깨져 보임)

**투명도 지뢰 4개** (시간 낭비 순):
1. **`transparent:true`를 생성 시점부터** 켜둘 것. 런타임 토글은 셰이더 재컴파일 → 문 통과하는 바로 그 순간 50~200ms 끊김
2. **페이드 대상은 재질 인스턴스를 공유하면 안 됨.** 지금은 매번 새로 만들어 안전하지만, "색상으로 재질 캐싱" 리팩터를 하는 순간 벽 4개가 같이 사라진다 → `materials.js`에 주석으로 못 박을 것
3. **투명해지면 `depthWrite=false`.** 안 하면 유령벽이 뒤를 계속 가려 회색 사각형만 보인다
4. **외곽선 제거가 여기서 결정적이다.** 지금 모든 메시가 `BackSide` 자식 외곽선을 달고 있어, 벽을 페이드하면 **검은 실루엣만 공중에 남는다.** 제거하면 드로우콜 절반(50→25), 콜라이더가 외곽선 두께만큼 부풀던 문제 해소, 그리고 raw `ShaderMaterial`이 `scene.fog`를 안 받는 문제까지 동시에 사라진다 → **M0에서 가장 먼저 할 것**

### 4.4 후처리 (sample1 룩)

**면셰이딩은 후처리가 아니라 재질이다.** `MeshLambertMaterial({flatShading:true})`. 툰의 4단 램프는 "애니메이션" 느낌이지 "로우폴리 면" 느낌이 아니다. Lambert는 fog·opacity·emissive를 다 지원해서 벽 페이드와 램프 요구를 전부 충족한다. `LOOK.mode = 'flat'|'toon'` 스위치는 2줄이니 A/B 비교용으로 남긴다.
> `BoxGeometry`는 이미 법선이 분리돼 있어 벽·책상은 안 변한다. 실제로 달라지는 건 실린더·이코사헤드론·스카이돔·그리고 **모든 GLTF 에셋** — sample1의 룩이 사는 지점이 정확히 거기다.

**패스는 하나로 합친다** (그레인+색보정+비네트). 서로 의존이 없고 이웃 픽셀 샘플링도 없어서 나눌 이유가 0이다. 나누면 풀스크린 왕복만 3배.

```
RenderPass → OutputPass → GradePass(renderToScreen)
```
> ⚠️ **r185 색공간 함정 — 반드시 터지는 지점.**
> `renderer.outputColorSpace`는 **기본 프레임버퍼에 그릴 때만** 적용된다. 렌더타깃에 그리는 순간 선형 공간으로 쓰이고 아무도 되돌리지 않는다. **`OutputPass`가 톤매핑+sRGB 인코딩을 하는 컴포넌트이고, 선택사항이 아니다.**
> 빠뜨리면 중간톤이 어둡고 탁해지는데 — **버그처럼 안 보이고 "분위기 있는 조명"처럼 보인다.** 그래서 조명을 올려 보정하게 되고, 이후 모든 조명 결정이 깨진 기반 위에 쌓여 전부 다시 해야 한다. **컴포저를 넣는 첫 커밋에서 조명을 건드리기 전에 함께 넣을 것.**
>
> **그리고 `OutputPass`가 마지막이 아니다** — 색보정 패스를 그 *뒤*에 둔다. 그래야 보정이 **디스플레이 기준 sRGB 값** 위에서 동작하고, 참조 이미지를 스포이드로 찍어 잡은 감이 그대로 먹는다. 선형 공간에서 보정하면 같은 계수가 전혀 다르게 동작한다.

> ⚠️ **안티에일리어싱 회귀**: `WebGLRenderer({antialias:true})`는 렌더타깃에 그리는 순간 **아무 일도 안 한다.** 면 분할된 로우폴리 실루엣에서 매우 잘 보인다. 컴포저 렌더타깃에 `samples: 4`(WebGL2 MSAA)로 해결. SMAAPass 쓰지 말 것.

**그레인은 `vUv`가 아니라 `gl_FragCoord` 기준 고정 가상 스케일로.** UV 기준이면 해상도와 `devicePixelRatio`에 따라 입자 크기가 변해서 내 모니터에선 맞고 레티나에선 TV 노이즈가 된다.

**안개**: `scene.fog = new THREE.Fog(...)` (지수형 아닌 선형 — 시작 거리와 지평선 세기를 직접 튜닝). **fog 색 = 스카이돔 지평선 색**이어야 경계선이 안 생긴다.
> ⚠️ **안개는 아무 효과도 없어 보일 것이다.** 방 하나뿐이고 유일한 원거리 물체인 스카이돔은 `fog:false`이기 때문. **`world/exterior.js`(넓은 지면 + 원경 언덕)를 같은 커밋에 넣어야** 안개에 대상이 생긴다. 이 모듈은 완전한 leaf라 1일차부터 병렬 제작 가능.

### 4.5 에셋 파이프라인
공유 `LoadingManager` 하나로 GLTF+텍스처+오디오 진행률을 통합.

**`restyle(root, {mode})` 3가지 모드** — 사용자가 여러 방법을 실험하고 싶어하므로 전부 지원:
- **KEEP** — 구워진 텍스처 유지하되 **`MeshStandardMaterial` → `MeshLambertMaterial`로 강등.** PBR 재질을 Lambert용 조명 씬에 그대로 두면 밝기/대비가 어긋나 캐릭터만 칙칙하게 "붙여넣은" 티가 난다
- **TINT** — KEEP + `material.color` 치환. color는 map에 곱해지므로 텍스처의 명암 디테일은 살고 색조만 팔레트로 끌려온다. **버텍스 컬러 에셋에 맞는 모드**
- **REPLACE** — 맵 버리고 팔레트 색 지정. 색 결정 순서: ① 재질명 매핑 → ② 원본 색과 HSL 최근접 → ③ **이름 해시**(난수 쓰면 새로고침마다 색이 바뀌어 버그로 오인)

> 방금 받은 GLB는 재질명이 `mat11, mat13, mat18…` 식 무의미한 이름이라 ①이 안 먹는다 → **②③ 폴백이 실제로 중요하다는 게 검증됐다.** 에셋마다 재질명·타입·색·맵 유무를 찍어주는 `logMaterials(root)` 헬퍼를 같이 만들 것.

**정규화** (`fitHeight`/`fitSize`/`recenterXZ`/`dropToFloor`): Poly Pizza 에셋은 단위와 정면 축이 제각각이라, 없으면 에셋마다 매직넘버를 영원히 손으로 맞추게 된다.

> ⚠️ **sRGB 함정 — 텍스처 실습에서 반드시 만난다.** `TextureLoader`로 직접 부른 색상 텍스처는 `colorSpace`를 손으로 `SRGBColorSpace`로 지정해야 한다. GLTFLoader는 GLTF 내장 텍스처에 한해 자동 처리한다. 즉 **"GLTF는 잘 나오는데 내가 붙인 PNG만 물빠져 보인다"**면 이것이다. 반대로 노멀맵·러프니스맵은 선형이라 건드리면 안 된다.

**로딩 중 응답성**: 프리미티브 월드를 먼저 만들고 렌더 루프를 즉시 돌린다. GLB는 최종 트랜스폼이 잡힌 빈 `Group` + 색 박스 플레이스홀더 자리에 나중에 꽂힌다. 캐릭터도 캡슐 스탠드인을 먼저 둬서 **A·B 레인이 에셋 없이 개발 가능**하게 만든다.
> `#loading`은 `onLoad` **또는 3초 타임아웃 중 먼저**. 에셋 경로 오타 하나로 게임이 검은 화면 뒤에 영원히 갇히면 안 된다 — 첫 배포에서 실제로 일어날 일이다.

### 4.6 오디오
코어에 전부 있어 **vendoring 0개**. `listener`는 camera의 자식으로.

> ⚠️ **오토플레이 게이트**: 브라우저는 제스처 전엔 `AudioContext`를 suspended로 둔다. **이미 있는 `#loading` 오버레이를 "시작하기" 버튼으로 바꾸는 게 정답** — 제약을 자연스러운 타이틀 화면으로 바꾸고 진행률 표시 자리도 생긴다. 버퍼는 게이트 *전에* 디코드해두고 클릭 핸들러에서 `play()`만 호출해야 iOS Safari에서도 동작한다. (오버레이를 먼저 닫고 전역 첫 클릭을 후킹하는 방식은 데스크톱 Chrome에서만 되고 Safari·iframe에서 조용히 실패한다.)

- **SFX는 3~4개 voice 풀**로. `Audio` 하나는 동시 1개만 재생돼서 발소리(~2Hz)가 계속 리셋된다
- **`PositionalAudio` 기본값은 방 스케일에 안 맞는다** — `refDistance=1` + inverse 모델이면 문간에서 램프 소리가 안 들린다. linear + refDistance 1.5 + maxDistance 10
- **탭 전환 시 suspend/resume.** 백그라운드 탭에서 BGM이 계속 나오는 건 링크를 닫게 만드는 1순위 이유
- 포맷은 `.mp3` 단일. BGM ≤1.5MB(짧게 루프), SFX ≤30KB

## 6. 검증

**빌드 단계가 없어 import 오류가 런타임까지 조용히 통과한다.** 이게 이 프로젝트에서 가장 잡기 어려운 유형이라 자동 검사를 만든다.

1. **문법** — 모듈마다 `node --check`
2. **import 그래프 검증기** (`tools/check-imports.mjs`) — importmap을 파싱해 진입점부터 따라가며 ① 모든 specifier가 실제 파일로 해석되는지 ② **파일명 대소문자·공백이 디스크와 정확히 일치하는지**
3. **에셋 사전검사** — 새 GLB마다 압축 확장·텍스처 크기·UV/스킨 유무·재질명 자동 리포트
4. **렌더 스모크 테스트** — `tools/render-check/shot.mjs`(로컬 서버 + 헤드리스 Chrome 스크린샷 + 콘솔 오류 수집), `move-check.mjs`(키입력 시뮬레이션), `audio-check.mjs`(실제 클릭+오디오 재생 확인), `zoom-check.mjs`(휠 줌 확인)
5. **사용자 육안 확인** — 4번이 되더라도 최종 판단은 사람이

**마일스톤별 확인 항목**
- M1: 걸어다닐 수 있나 · 벽 통과 안 하나 · 방이 답답하지 않나 · 카메라가 벽 밖으로 안 나가나 · **드래그 끝날 때 램프가 잘못 켜지지 않나**
- M2: sample1과 톤이 비슷한가 · 그레인이 과하지 않나 · **화면이 어둡거나 탁하지 않나**(→ OutputPass) · 면 실루엣이 계단지지 않나(→ MSAA)
- M3: 캐릭터 크기가 방·가구와 맞나 · 텍스처가 물빠져 보이지 않나(→ sRGB)
- M4: 방 이동이 자연스러운가 · 가로막는 벽이 제대로 사라지나 · 문에 끼지 않나
- M5: **다른 기기·브라우저에서** 지인이 받은 링크가 실제로 열리나
